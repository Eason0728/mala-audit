## 3. 初始化與匯入（部署完成後，在 Apps Script 編輯器各執行一次）

順序不能顛倒：

1. 執行 `setup()`
   - 建立四個新分頁：`稽核紀錄`、`抽查明細`、`品項庫`、`設定`。
   - 把央廚／金山店／光復店／六張犁店四個分頁補上金庫欄位
     （零找金、零用金、小費是否正確、小費金額），原本的「複盤異常說明」自動搬到最後一欄——
     版面會變成和小辛辣光復店一樣。
   - 重複執行不會壞（已做過的會自動跳過）。
2. 執行 `importHistory()`
   - 把五個分頁 2026 年 1–7 月的紀錄匯進資料分頁，異常說明自動拆成逐項明細。
   - 歷史異常的「原因分類」一律標成 `未分類`（因為當時沒有這個欄位）。
   - 電腦上測過的結果：34 筆紀錄、27 筆異常明細、**12 段異常文字全部解析成功**，
     沒有任何一筆需要人工補救。
   - 重複執行不會重複寫入。

## 4. 設定通行碼與品項庫（在試算表裡直接改）

1. `設定` 分頁：把「會計通行碼」「主管通行碼」兩列的值（預設是 `請設定`）改成你要的密碼。
   **密碼只寫在這裡，不會出現在程式碼或 GitHub 上。**
2. `品項庫` 分頁：請會計把各店月底盤點表的品項貼進來，四欄分別是
   `店代碼`、`品項`、`單位`、`狀態`。店代碼對照：
   | 店代碼 | 店名 |
   |---|---|
   | `sxl-gf` | 小辛辣光復 |
   | `ck` | 央廚 |
   | `mzt-gf` | 墨竹亭光復 |
   | `mzt-js` | 墨竹亭金山 |
   | `mzt-lzl` | 墨竹亭六張犁 |
   狀態欄填 `啟用`（不想再抽到的品項改成 `停用`，歷史紀錄仍保留）。
   歷史異常出現過的品項（鴨血、蟹黃醬等）`importHistory()` 已自動補進去了，不用重打。
   **這一步做完，隨機抽 20 項才抽得到東西**——品項庫是空的就抽不出來。

## 6. 之後每個月怎麼用

- 會計到店 → 手機開網址 → 選店選月 → 按「隨機抽 20 項」→ 現場逐項填盤點數與複盤數 →
  自己判「正確／異常」→ 異常選原因 → 填金庫三項 → 送出。**現場就結束，不用回辦公室補打。**
- 那個月不查 → 在總覽按「標記輪休」。
- 主管：開同一個網址、用主管碼登入，只能看不能改；報告頁可以列印或存 PDF。
