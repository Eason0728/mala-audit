## 2. 改程式的標準流程（clasp，帳號 madesiaosinla）

```
cd ~/mala-audit && clasp pull        # 先拉，避免蓋掉在網頁編輯器上的修改
# 改 apps-script/Code.gs 或 Import.gs
clasp push
clasp create-version "說明"
clasp update-deployment AKfycbz5l_aH_qypN6HK6UDT__5NLZDk4A2clyqeqvJzx5JrL9SBVeH5GyDYBCW3gv-CDy7fFQ -V <版本號>
clasp list-deployments               # 確認版本號有跳
```

- **`clasp push` 只更新 @HEAD，正式網址不會變**——一定要 create-version＋update-deployment。
  （2026-08-01 踩過：以為修好了，其實跑的還是舊版。）
- **版本旗標是大寫 `-V`**；小寫 `-v` 是印版號，會安靜地什麼都沒做。
- **絕不可 `clasp create-deployment`（建新部署）**——會產生新網址，前端立刻斷線。永遠 update 既有 ID。
- 部署後生效有幾秒延遲，馬上呼叫可能還是舊版，等一下再試。

## 3. 兩個踩過的坑（改程式前先看）

1. **年月會被試算表存成日期**：`2026-01` 這種字串寫進儲存格會被自動判讀成 Date，
   讀回來就不是原字串，前端月份比對全部落空。解法：寫入前用 `setNumberFormat('@')`
   把欄位鎖成純文字（`ensureTextColumns_`，稽核紀錄 A/C/E/O、抽查明細 A/C）。
   **setup 與 doPost 送出路徑都要鎖**——只鎖 setup 的話，新送出的紀錄照樣會變 Date。
2. **curl 測 GAS 會騙人**：POST 到 /exec 會回 302 轉址，`-X POST` 會強制轉址後那跳也用 POST，
   而 Google 的 echo 端點只收 GET，結果回 405 看起來像失敗。正確寫法是不要加 `-X POST`：
   `curl -sL -H "Content-Type: text/plain" -d '{"action":"getAll"}' "$URL"`

## 5. 前端託管（**待決定，尚未上線**）

GitHub Pages 在 private repo 需要付費方案，所以有兩條路：

- **A：把 repo 改成公開**（同你其他 app 的做法）＋ 啟用 Pages。
  代價：`js/config.js` 裡的後端網址會出現在公開 repo，而目前沒有通行碼，
  等於任何找到 repo 的人都能讀寫稽核資料。已放 `robots.txt` 擋搜尋引擎，但擋不住 GitHub 搜尋。
- **B：repo 保持 private，前端改用 Netlify 拖檔部署**（同墨竹亭耗損表的做法）。
  網址一樣是公開可存取（不然會計開不了），但程式碼與後端網址不會被 GitHub 搜尋掃到。

兩條路的共通點：**只要沒有通行碼，拿到網址的人就能讀寫**。真正要擋，只能開回第 4 節的通行碼。
