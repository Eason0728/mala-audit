# 稽核系統（月初盤點及金庫抽查）— spec.md
版本：v1 草稿 / 2026-08-01（待 Eason 確認；需求見 requirements.md v2）

## 1. 系統全貌

```
會計手機 / 主管手機電腦
        │  (HTTPS)
靜態網頁前端（vanilla JS，單頁 app，手機優先）
        │  POST text/plain（JSON，避 CORS preflight，同調撥/巡檢慣例）
Apps Script Web App（container-bound，部署帳號 madesiaosinla@gmail.com）
        │
Google Sheet「2026年月初盤點及金庫抽查明細表」
  ├─ 既有分頁（五張分表，人看的年度總表）→ 系統回寫
  └─ 新增分頁：稽核紀錄／抽查明細／品項庫／設定（機器讀寫的正本）
```

- 專案目錄 `~/mala-audit`：`index.html`＋`js/`＋`css/`＋`apps-script/Code.gs`。
- 與庫存/打卡/績效/巡檢/調撥同路數：無框架、無 build step、前端可先本機開檔測。
- **資料正本＝新增的結構化分頁**；既有五張分表降級為「顯示層」，每次送出由後端回寫，
  主管照舊打開 sheet 也看得懂。

## 2. Sheet 分頁設計

### 2.1 既有分頁（顯示層，回寫不重建）
- **2026-08-01 實查 xlsx 修正**：五張「分表」實際是五個**獨立分頁（tab）**，分頁名稱＝
  `小辛辣光復店`／`央廚`／`金山店`／`光復店`／`六張犁店`（實際順序金山在光復前）。
  **一律按分頁名稱對應店代碼（見 §5），不看順序**——名稱無歧義，順序就不重要。
- 初始化腳本會把第 2–5 張分表**補上金庫三欄＋小費金額欄**（欄序、標題文字對齊第一張）。
- 回寫規則：送出「某店某月」稽核 → 找到該店分表的該月列，寫入：
  複盤正確數量、正確率、零找金、零用金、小費是否正確、小費金額、複盤異常說明。
  標記輪休 → 該月「複盤正確數量」欄寫 `輪休`（同現有用法）。
- **2026-08-01 T8 實查定案**：座標常數在 `apps-script/sheet-map.json`（header_row=1、月列=2–13 五分頁一致；
  小辛辣光復店 9 欄 A–I，其餘四分頁僅 5 欄 A–E，金庫欄由 setup() 補）。
  「正確率」欄**全部是公式 `=C{row}/B{row}`**；輪休月 D 儲存格完全空白。
  **回寫規則**：submitAudit 寫數值欄（C 等），D 欄一律寫入公式 `=C{row}/B{row}`（本來就有公式也重寫，冪等）；
  標記輪休 → C 欄寫 `輪休`、D 欄清空。

## 3. 前端（單頁 app，五個畫面）

1. **登入**：輸入通行碼 → 後端驗證回角色（`accountant`／`viewer`）。角色存 sessionStorage。
2. **總覽（首頁）**：年份切換；5 店 × 12 月狀態格（已稽核＝正確率、輪休、未記錄）；
   點格子進單月報告。主管與會計都看得到；「開始稽核」「標記輪休」按鈕只有會計看得到。
3. **稽核填寫**（會計限定）：
   - 選店＋月份（預設當月；同月已有紀錄 → 明示「將覆蓋 X 月 X 日那筆」需確認）。
   - **填寫方式兩選一**（2026-08-07 新增，記在 localStorage `audit_fill_mode`，跨 session 記住）：
     - `完整 20 項`（原行為）：抽滿 20 項逐項核定，分母＝實際清單項數。
     - `只填異常項`：只輸入異常的品項，其餘視同正確，**分母固定 20**
       （＝`Config.SAMPLE_SIZE`）。1 項異常 → 19/20 → 95%；0 項異常 → 100%。
       此模式下不顯示抽樣鈕與正確／異常核定鈕（每項固定「異常」），仍要填盤點數／
       複盤數／異常原因；異常數 > 20 擋下送出。**抽查明細只寫入異常那幾列**——
       沒被輸入的品項不逐項留痕，只計入分母（改用此模式後，`⚠ 抽過` 標記與
       「各店異常率」的分母來源不受影響，但明細不再有「這 20 項是哪 20 項」的紀錄）。
     - 兩模式草稿分開存（只填異常項的 key 多後綴 `_anomaly`），切模式不會弄丟另一邊；
       送出成功時兩把一起清。
   - **抽樣**（僅完整模式）：「隨機抽 20 項」一鍵從品項庫（啟用中）抽出草稿；每項顯示歷史標記
     （`⚠ 2026-03 抽過`，資料來自抽查明細）；單項可「換一項」重抽、可手動搜尋替換、可增刪
     （少於或多於 20 項時送出前提醒但不阻擋）——記憶只參考、不干涉（需求 §4.1）。
   - **手動加入品項不綁定品項庫**（2026-08-07 Eason 指示）：名稱框可自由打，
     品項庫有的自動帶單位（可改）、庫裡沒有的自己填單位就能加。單位不可省——
     異常說明要組 `盤點27盒`，缺單位那行會少一塊。自訂品項只用於這一筆紀錄，
     **不會自動寫回品項庫**（要進品項庫仍是手動貼「品項庫」分頁）。
   - 每項填盤點數／複盤數 → 會計點「正確」或「異常」；異常展開原因下拉＋備註。
   - 金庫區塊：零找金、零用金（顯示標準 1 萬）各點正確/不正確；小費金額＋相符/不相符。
   - **草稿防丟**：每次輸入即存 localStorage（key=`draft_{record_key}`），斷網/關頁可續填；
     送出成功才清草稿；送出失敗（斷網）→ 草稿保留＋「重試送出」。
4. **報告（可列印 → PDF）**：
   - 單店單月：表頭（店/月/日期/會計）＋20 項明細＋金庫結果＋異常原因；print CSS 一頁為目標。
   - 年度總表：選店，重現分表樣式（12 月 × 各欄）。
   - 列印一律走瀏覽器列印存 PDF（同巡檢/庫存 app；PDF 檔名行為要在真瀏覽器驗，庫存 app 教訓）。
5. **異常分析**：年份範圍篩選；(a) 累犯品項排行（品項 × 異常次數 × 出現店別與月份）；
   (b) 原因分類統計（次數）；(c) 各店異常數。純表格＋簡單長條（CSS bar，乾淨大方向，不灑圖）。

資料流：登入後一次 `getAll` 拉回（設定、品項庫、當年稽核紀錄＋抽查明細），
總覽/報告/分析全部前端計算——資料量小（5 店 × 12 月 × 20 項/年），不做分頁查詢。

## 4. 後端（Apps Script，doPost action 分流）

| action | 權限 | 入參 → 回傳 |
|---|---|---|
| `auth` | 公開 | `{code}` → `{role}` |
| `getAll` | 兩種角色 | `{code}` → `{config, items, records, details}`（**全年份全量回傳**，年份篩選在前端做——抽樣記憶要看跨年歷史，且資料量小） |
| `submitAudit` | 會計 | `{code, record, details[]}` → `{ok, record_key}`；覆蓋語意＝稽核紀錄同 key 整列取代＋抽查明細先刪後寫＋回寫顯示分表，三步在同一次執行完成 |
| `markRest` | 會計 | `{code, store, month}` → `{ok}`；寫稽核紀錄（狀態=輪休）＋回寫分表 `輪休` |

- 全部 POST、Content-Type text/plain、body JSON（CORS 慣例同其他 app）。
- 每個 action 先驗通行碼；會計碼可做全部，主管碼只能 `getAll`。
- `importHistory()`（手動跑一次的函式，不開放前端）：解析既有五張分表 1–7 月 →
  產稽核紀錄；異常說明字串以 regex 拆回抽查明細（原因=`未分類`），拆不動的整段放備註列。
  **已知限制**：歷史的「正確品項」sheet 上沒逐項記錄，只匯入異常項——
  抽樣記憶對 1–7 月只認得出過異常的品項（Eason 已知悉的取捨，寫在這裡防未來誤會）。
- `setup()`：建四個新分頁＋補第 2–5 分表金庫欄＋寫入設定預設值。
- **品項庫首批**：會計把各店月底盤點表的品項＋單位直接貼進品項庫分頁（sheet 原生編輯，不用寫程式）；
  `importHistory()` 會把歷史異常出現過、但品項庫還沒有的品項自動補進去（狀態=啟用）。

## 5. 共用契約（跨任務都要照抄的格式；逐字元定義＋範例）

**店代碼表**（前後端、分頁回寫、匯入共用；**以分頁名稱逐字元對應，不看順序**）：
| 店代碼 | 店名 | sheet 分頁名（逐字元） |
|---|---|---|
| `sxl-gf` | 小辛辣光復 | `小辛辣光復店` |
| `ck` | 央廚 | `央廚` |
| `mzt-gf` | 墨竹亭光復 | `光復店` |
| `mzt-js` | 墨竹亭金山 | `金山店` |
| `mzt-lzl` | 墨竹亭六張犁 | `六張犁店` |

- **record_key**：`{店代碼}_{YYYY-MM}`，底線分隔、月份補零。範例：`sxl-gf_2026-08`。
- **月份顯示對照**：`2026-01`→`一月` … `2026-12`→`十二月`（分表回寫、報告顯示用）。
- **正確率**：`Math.round(正確數/抽查數×100)`，顯示加 `%`。範例：19/20 → `95%`。
  只填異常項模式改用 `Format.anomalyOnlyCounts(異常項數, 20)`：
  `sample_count` 固定 20、`correct_count = 20 − 異常項數`（夾在 0 不出現負數）。
  兩種模式寫進試算表的欄位形狀完全相同，顯示分頁的 D 欄公式 `=C{row}/B{row}` 不必改。
- **異常說明自動組字**（一字不差對齊現有 sheet 風格，注意內文用「覆盤」、標題用「複盤」）：
  格式＝`{序號}.{品項}:盤點{盤點數}{單位}，覆盤{複盤數}{單位}`，
  多筆以**換行（\n）**連接（2026-08-01 實查 CSV 修正：儲存格內是換行，不是空格），結尾無多餘換行。
  範例：`1.鴨血:盤點27盒，覆盤32盒\n2.米血:盤點9包，覆盤8包`
  （冒號半形、逗號全形、數字照輸入原樣不補零；匯入解析需容忍結尾多餘換行/空白）。
- **判定值**：`正確`／`異常`；金庫：`正確`／`不正確`；小費：`相符`／`不相符`；
  狀態：`已稽核`／`輪休`。全系統只用這些字串，禁止同義詞（防 2026-07-18 leadfinder 對不上 key 的教訓）。

## 6. 異常原因分類（設定分頁預設值）

`盤點錯誤（門市盤錯）／損耗未記／單位混淆／進出貨未入帳／其他`
——「其他」必填備註。會計改設定分頁即可增減，前端下拉動態讀。

## 7. 錯誤處理

- 送出失敗（斷網/逾時）：草稿保留 localStorage＋顯示重試；重試用同 record_key，覆蓋語意保證不重複。
- 覆蓋既有紀錄：前端強制確認一次（顯示原紀錄日期與正確率）。
- 後端驗證：record_key 格式、店代碼在代碼表內、判定值在枚舉內，不合法整筆拒收回錯誤訊息。
- 通行碼錯誤三次 → 前端冷卻 30 秒（同其他 app 的輕量做法，不做帳號鎖定）。
