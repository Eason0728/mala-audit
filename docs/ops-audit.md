# 營運稽核表（2026-08-11 新增）

月初盤點抽查之外的第二張表。同一個網址、同一組通行碼、同一本試算表，但**資料完全分開**。
登入後先進「選單」，兩張表擇一。

來源：Eason 2026-08-11 指定參照 https://clever-gelato-bff2d9.netlify.app/ 的
「營運管理」＋「品牌形象」共 19 項。

## 決策紀錄（為什麼長這樣）

| 決定 | 選擇 | 理由 |
|---|---|---|
| 適用店別 | 五節點全部 | 跟月初盤點一致，不另開一套店別清單 |
| 頻率 | 每月一次，同盤點一趟 | `record_key` 沿用 `{店代碼}_{YYYY-MM}` |
| 缺失照片 | **不做** | 存照片要用雲端硬碟服務，Apps Script 靠靜態掃描決定 OAuth 範圍，那個服務名只要出現在程式裡就得請 Eason 重新授權一次，還多一個會壞的環節。缺失改用文字說明 |
| 回寫顯示分頁 | **不回寫** | 那五個分頁是盤點專用的 A–I 格式，硬塞會弄壞主管既有的表 |
| 合格率分母 | 固定＝19（細項總數） | 未檢查算在分母裡，查一半不會顯示成 100% |

## 檢查表

`js/ops-checklist.js` 是唯一正本，19 項分四個群組：

- 營運管理｜消防安全 7 項、營運 2 項
- 品牌形象｜環境清潔 6 項、食安 4 項

⚠ 項目 id 是位置算出來的（`c{大類序}g{群組序}i{項目序}`），**位置就是身分**。
中間插入或刪除會讓其後所有項目位移、歷史明細對不回原本的項目。
要加項目一律加在該群組**最後面**。明細列同時存了大類／群組／項目全文，
所以就算 id 位移，試算表本身仍看得懂。

## 資料

兩個新分頁（不存在時由 `ensureOpsTabs_` 自動建立，送出路徑也會建）：

**營運稽核紀錄** A–O
`record_key／店代碼／年月／狀態／稽核日期／稽核人員／細項總數／合格數／未完成數／未檢查數／追蹤數／合格率／缺失摘要／備註／提交時間`

**營運稽核明細** A–J
`record_key／店代碼／年月／項目編號／大類／群組／檢查項目／判定／追蹤／說明`

- 判定枚舉逐字元：`合格`／`未完成`／`未檢查`（與盤點的「正確／異常」是不同的一組，不要混用）
- 追蹤欄寫 `是` 或留空
- 缺失摘要組字：`{序號}.{群組}－{檢查項目}:{說明}`，多筆換行連接（`Format.buildOpsSummary`）
- 文字欄鎖定：紀錄 A/C/E/O、明細 A/C（年月不鎖會被試算表存成 Date，前端比對全落空）

## 規則

- **判「未完成」必填說明**，前端擋一次、`validateOpsDetails_` 再擋一次。
  這是這張表存在的理由：只寫「未完成」三個字，下個月沒人知道要改什麼。
- **稽核人員必填**：報告上要看得出是誰查的。
- 覆蓋語意同盤點：同 `record_key` 整列取代，明細先刪該 key 全部列再寫入。
- 草稿 `ops_draft_{record_key}`、上次店別 `ops_last_store`（與盤點的 key 前綴分開）。

## 前端

| 檔案 | 負責 |
|---|---|
| `js/views/home.js` | 選單（兩張卡片，各顯示本月幾家已送出） |

`navigate('overview')` 這種直接指定分頁的呼叫會靠 `TAB_MODULE` 自動把區塊切對。
